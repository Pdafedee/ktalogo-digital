Capítulo 01
Qué es un ejecutable y qué gana tu negocio

Hasta hoy, para abrir Ktalogo-Dgital cada PC necesitaba tres cosas: Python instalado, las dependencias descargadas y la carpeta del proyecto completa. El ejecutable condensa todo eso en un solo archivo: KtalogoDgital.exe. Se copia a un pendrive, se pega en cualquier Windows y abre con doble clic. Nada más.

Técnicamente, el asistente CREAR-EJECUTABLE.bat usa PyInstaller (a través de flet pack, la ruta oficial de Flet) para meter en un paquete único tres capas: tu código Python, todas las librerías (Flet, ReportLab, Pillow…) y el propio motor visual de Flet con su icono integrado. El resultado no necesita lectura de registro, no instala servicios y no toca el sistema: es una app portable en toda la extensión de la palabra.

🎒 Portabilidad total

El .exe va en el USB junto a tu carpeta data\ y tu negocio abre en la PC del socio, la casa o la feria. Sin instaladores ni soporte técnico.

🧘 Cero mantenimiento

Se acabó el «Python se desactualizó» o «pip falló con el proxy». El .exe lleva todo dentro: lo que compilas hoy funciona igual el año que viene.

🛡️ Código protegido

El .exe empaqueta y compila tu código: nadie lee ni edita los archivos fuente desde la máquina de ventas. Ideal si el equipo lo comparte con terceros.

⚡ Arranque directo

Doble clic y la vitrina está en pantalla, con el icono azul de la «K» en la barra de tareas. Sin consolas de fondo ni ventanas negras.

Qué NO cambia con el ejecutable

El .exe es exactamente la misma aplicación: mismos módulos, misma base de datos y mismas reglas de roles. Tu data\ sigue siendo JSON que migra a SQLite solo cuando crece; el modo web con QR para el celular sigue disponible; y el proyecto fuente (Python) sigue siendo tu versión de desarrollo, donde preparas las mejoras antes de recompilar. Piénsalo así: el ejecutable es la copia de trabajo, el proyecto Python es el taller.

Regla de oro v3.0: compila el .exe desde tu PC principal (donde están tus datos y tu .venv probado), y reparte después. Así cada copia sale con la misma versión y el mismo comportamiento que ya verificaste.

Capítulo 03
Prepara el PC de compilación (2 minutos)

Solo la PC donde compilas necesita preparación; las PCs destino no necesitan nada. Si ya usas la plataforma en tu máquina, el paso 1 ya lo tienes hecho.

1
Ten el proyecto v3.0 en el disco. Descomprime el paquete ktalogo-digital-v3.0.0-EJECUTABLE.zip ENCIMA de tu carpeta actual (sobrescribe) o clónalo desde GitHub con git clone. Verifica que CREAR-EJECUTABLE.bat esté en la raíz junto a INSTALAR.bat.
2
Ejecuta INSTALAR.bat una vez (si no lo hiciste antes). Crea Python + el entorno .venv con todas las dependencias. El asistente del ejecutable reutiliza ese .venv, así que no duplica descargas.
3
Pasa el Doctor. Doble clic en scripts\doctor.py (o ejecútalo): debe decir «TODO EN ORDEN» y reportar v3.0.0. Si marca archivos antiguos, re-extrae el zip encima.
4
Espacio y antivirus. Deja ~3 GB libres y, si tu antivirus es celoso, agrega la carpeta del proyecto a sus exclusiones por unos minutos: los compiladores generan archivos temporales que los antivirus a veces interceptan y eso corta la build a mitad.
¿Y si quiero compilar en una PC nueva? Solo necesita: Windows 10/11 64-bit + Python 3.10+ (o ejecutar INSTALAR.bat) + internet para la primera descarga. Nada de Flutter ni herramientas gigantes: por eso elegimos la ruta PyInstaller para la v3.0.
Capítulo 04
CREAR-EJECUTABLE.bat · las 6 fases

Doble clic y espera. El asistente muestra cada fase en pantalla; esto es lo que hace por dentro y cuánto tarda (la primera vez descarga más; después queda cacheado).

1
Localiza Python (instantáneo). Primero busca el .venv de tu instalación; si no existe, usa el Python del sistema (3.10+) o te avisa para que pases antes INSTALAR.bat.
2
Dependencias + PyInstaller (2-4 min). Instala requirements.txt, la CLI de Flet (flet[cli]) y PyInstaller dentro del mismo .venv. Tu instalación de la app no se toca: son herramientas de build.
3
Compila el .exe de un solo archivo (3-6 min). flet pack descarga (una vez) el motor de Flet para Windows, le incrusta tu icono ktalogo.ico y los metadatos (nombre, versión 3.0.0, copyright), y produce build-exe\onefile\KtalogoDgital.exe.
4
Compila la carpeta portable (3-6 min). El mismo proceso con la bandera -D (onedir): en vez de un archivo, una carpeta KtalogoDgital\ que arranca mucho más rápido porque no se auto-descomprime en cada inicio.
5
Ensambla release\ (segundos). Copia los dos formatos a una carpeta limpia y añade .env.example como recordatorio de configuración opcional. Esta carpeta es la que repartes.
6
Resumen y apertura. Te muestra los dos resultados, el siguiente paso (copiar data\ si quieres llevar tus datos) y abre la carpeta release\ en el Explorador.

Actualizar el .exe cuando salga una versión nueva

1
Actualiza el proyecto (zip nuevo encima, o git pull si usas GitHub). Tu data\ no se toca.
2
Recompila con CREAR-EJECUTABLE.bat. En 6-12 min tienes el .exe de la versión nueva con tu mismo .venv.
3
Reparte: sustituye el .exe en cada PC manteniendo la data\ local de cada una. Listo.
Conexión con GitHub (si ya subes tu código): además de compilar local, puedes clonar el proyecto en cualquier PC con git clone + INSTALAR.bat y compilar ahí mismo. Y el APK de Android ya se construye en la nube con GitHub Actions — el ejecutable de Windows podría seguir el mismo camino si algún día quieres compilar sin PC local.
Capítulo 07
Solución de problemas y checklist final

Los sustos del ejecutable son pocos y siempre tienen la misma cura. Estos son los cinco que verás alguna vez.

Windows dice «Protegió tu PC» (SmartScreen) y no abre
Es el filtro de apps sin firma digital, no un virus: pulsa Más información → Ejecutar de todas formas. Solo pasa la primera vez por .exe.
El antivirus borró o bloqueó el .exe
Restaura el archivo desde la cuarentena y agrega la carpeta release\ (o el .exe) a las exclusiones del antivirus. Los ejecutables de PyInstaller sin firma son sospechosos habituales para los antivirus celosos; con la exclusión, problema resuelto.
El .exe no abre y pide «VCRUNTIME140.dll» o similar
Falta el runtime de C++ de Microsoft (Windows lo trae casi siempre). Instala VC++ Redistributable x64 desde aka.ms/vs/17/release/vc_redist.x64.exe y reintenta.
La primera apertura tarda demasiado
El formato de 1 archivo se auto-descomprime en cada arranque (3-6 s normales; en USB 2.0 hasta 10 s). Para uso diario usa el formato carpeta portable, que arranca en 1-2 s.
«Puerto 8550 ocupado» al usar el modo web
Otro proceso lo usa (quizá una INICIAR-WEB anterior). Ejecuta con otro puerto: KtalogoDgital.exe --web --port 8560. El QR se genera con la URL correcta automáticamente.
Compilé pero release\ está vacía
La build falló en las fases 3-4: sube en la consola roja el motivo real (antivirus, disco lleno, pip sin internet). Resuelto eso, vuelve a ejecutar el asistente — es seguro reintentar, limpia su basura solo.
¿Puedo compilar sin internet?
La primera compilación necesita internet (descarga el motor de Flet y las librerías una sola vez). Después quedan cacheadas en tu PC: las siguientes compilaciones funcionan offline. Actualizar la app sí requerirá conexión otra vez porque llega una versión nueva de librerías.
